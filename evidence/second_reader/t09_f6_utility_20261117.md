# T09 second-reader audit — F6 utility-reporting semantics

**Date:** 17 November 2026  
**Reviewer:** ChatGPT (independent of the original Claude extraction)  
**Scope:** The hand-coded count behind F6 only. This is a semantic coding review of the `utility` field, not a full second read of the 35 papers.

## Coding rule

Count a work only when the sections read report a measure of legitimate-task performance or a directly interpretable proxy for legitimate-task completion (for example benign task success/accuracy, usefulness, capability under the task objective, utility under attack, or false rejection/over-blocking of benign tasks). Do **not** count:

- security outcomes alone (attack success, exploit rate, safety, suspicion or detector performance);
- qualitative discussion without a reported legitimate-task measure;
- computational cost, latency or runtime overhead alone.

This rule matches the manuscript’s wording “legitimate-task utility” and the rationale that a low attack rate is not useful if the agent simply does little.

### Correction

`rha` (W003, arXiv:2603.11337v1) reports a 25–31% median runtime overhead for locking. That is an enforcement cost, not a measure of whether legitimate tasks were completed. Its `utility` value is therefore recoded from a runtime-overhead string to `null`. The runtime figure remains in the extracted result and manuscript discussion; it is only removed from the F6 utility count.

### Clarification

`camel` (W108, arXiv:2503.18813v2) was already counted, but its ledger text described analysed failure modes rather than naming the utility measure. The field now states that AgentDojo legitimate-task utility is reported and was largely retained except in the travel suite.

## Semantic spot checks

- `impossible` reports performance on the original benchmarks alongside cheating rates; the original-benchmark pass rate is legitimate-task performance.
- `silent` reports false-rejection/over-blocking and benign user-prompt resolution, so it is a direct legitimate-task proxy.
- `cot` reports capability in the low-optimisation regime alongside monitorability/reward-hacking outcomes; it is legitimate-task capability rather than a security-only score.
- Category-D “usefulness” records pair benign-agent/task performance with safety, which meets the rule.

## Consequence for the manuscript

After regeneration, F6 must read **15 of 35**: D 6/8, B 5/9, A 2/10 and C 2/8. “Under half” remains correct. The structural audit should derive these values from `paper/counts.json`; no count is to be typed into prose.

## Limits

This audit used the pinned extraction entries and targeted primary-source checks for ambiguous cases. It does not replace the outstanding human reading of the included works, and it does not certify that utility is absent from unread sections.
